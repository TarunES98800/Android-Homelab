# Configuring a Minecraft Java Server on Android

## 1. Introduction

After installing PaperMC, the next step is configuring the Minecraft server according to our requirements.

Minecraft provides a configuration file called `server.properties`, which controls many aspects of server behaviour.

Using this file, we can customize:

- Server name and description.
- Maximum number of players.
- Game mode and difficulty.
- World generation settings.
- Server network port.
- View distance and simulation distance.
- Player authentication.
- Whitelist functionality.

We will also explore useful Minecraft console commands for managing players and server settings.

This tutorial uses the Android-Homelab implementation running PaperMC inside Termux on a Redmi Note 8 Pro.

## 2. Understanding server.properties

The `server.properties` file is located inside the Minecraft server directory.

In our setup:

```text
~/minecraft/server.properties
```

It contains configuration settings written as key-value pairs.

For example:

```properties
max-players=10
difficulty=normal
gamemode=survival
server-port=25565
```

Each line represents a particular server setting.

The value after the `=` symbol determines how the server behaves.

### Understanding the format

Consider:

```properties
max-players=10
```

Here:

- `max-players` is the property name.
- `=` separates the property from its value.
- `10` is the configured maximum player count.

Most settings should be edited while the server is stopped, then applied by restarting the server.

**Important:** PaperMC versions can generate different properties over time. Use the `server.properties` generated by your installed server version rather than replacing it with an outdated configuration copied from another tutorial.

## 3. Stopping the Minecraft Server Before Editing

Before modifying server configuration files, we should stop PaperMC gracefully.

### Step 1: Open the running tmux session

In the normal Termux shell, execute:

```bash
tmux attach -t minecraft
```

### Step 2: Stop PaperMC

Inside the Minecraft server console, execute:

```text
stop
```

Wait for the world to save and the Java process to terminate.

### Step 3: Return to the Termux shell

After the server stops, the terminal should return to the shell.

Now we can safely modify the configuration.

Before making major changes, it is good practice to create a backup:

```bash
cp ~/minecraft/server.properties ~/minecraft/server.properties.backup
```

This creates a separate copy of the configuration file.

## 4. Opening server.properties

First, enter the Minecraft directory:

```bash
cd ~/minecraft
```

Open the configuration file using Nano:

```bash
nano server.properties
```

You will see several configuration properties.

Use the keyboard or Termux's extra keys to navigate and edit the values.

To save changes:

1. Press `Ctrl + O`.
2. Press `Enter`.
3. Press `Ctrl + X`.

The changes will be stored in the file.

## 5. Important Server Properties

Let's examine the most useful configuration settings.

### 5.1 MOTD — Server Description

The Message of the Day (MOTD) is the description displayed in the Minecraft multiplayer server list.

Example:

```properties
motd=Android Homelab Minecraft Server
```

You can customize it to describe your server.

For example:

```properties
motd=Welcome to our Android Homelab Server!
```

This setting does not affect gameplay performance.

### 5.2 Maximum Players

Property:

```properties
max-players=10
```

This determines the maximum number of players allowed to play simultaneously.

For a small private Android homelab, you may start with:

```properties
max-players=3
```

or:

```properties
max-players=5
```

This is a configuration choice, not a guarantee that the phone can handle that many players smoothly.

Actual capacity depends on world complexity, player activity, plugins and hardware performance.

### 5.3 Game Mode

Property:

```properties
gamemode=survival
```

This controls the default game mode for new players and can be relevant when the server forces the configured mode.

Common values:

| Game Mode | Description |
|---|---|
| `survival` | Players gather resources and survive |
| `creative` | Players have access to creative building resources |
| `adventure` | Gameplay is restricted for adventure maps |
| `spectator` | Players can observe the world without normal interaction |

Example:

```properties
gamemode=survival
```

### 5.4 Difficulty

Property:

```properties
difficulty=normal
```

Available values:

| Difficulty | Description |
|---|---|
| `peaceful` | Hostile mobs do not normally spawn |
| `easy` | Easier survival difficulty |
| `normal` | Standard survival difficulty |
| `hard` | More challenging survival difficulty |

For a normal multiplayer survival experience:

```properties
difficulty=normal
```

### 5.5 Server Port

Property:

```properties
server-port=25565
```

Minecraft Java Edition normally uses TCP port 25565.

The server listens for incoming player connections on this port.

When a player enters a server address, the client uses the address and port to establish a connection.

For example:

```text
192.168.1.15:25565
```

The IP address is illustrative.

For our initial setup, keep the default port unless you have a specific reason to change it.

### 5.6 Server IP

Property:

```properties
server-ip=
```

For a typical Termux installation, leave this field empty.

An empty value tells the server to bind to the available network interfaces rather than restricting it to a particular IP address.

This is important when the phone needs to accept connections through both its local Wi-Fi interface and Tailscale.

Do not enter your public IP address here.

### 5.7 View Distance

Property:

```properties
view-distance=10
```

View distance controls how much world data the server sends to each player.

It is measured in chunks in each direction from the player.

A higher view distance generally means more world data must be loaded, processed and transmitted.

For an Android smartphone with limited resources, you can experiment with a lower value:

```properties
view-distance=6
```

This is a reasonable starting value for testing, not a guaranteed optimum.

### 5.8 Simulation Distance

Property:

```properties
simulation-distance=10
```

Simulation distance controls the area around players in which the server processes certain world activities, including entity ticking.

This is different from view distance.

For example:

- View distance controls how much world data is sent to clients.
- Simulation distance controls how far away certain game activities are processed.

For our Android server, try:

```properties
simulation-distance=4
```

Lowering simulation distance can reduce server workload, although the actual performance improvement depends on the world and player activity.

### View Distance vs Simulation Distance

| Feature | View Distance | Simulation Distance |
|---|---|---|
| Main purpose | Send world data to players | Process nearby world activity |
| Affects | Amount of world visible | Area where entities and game activity are updated |
| Performance impact | Network, memory and chunk work | Server processing workload |

These settings are useful when balancing gameplay experience and server performance.

## 6. World Generation Settings

Minecraft provides several properties that affect world creation.

### 6.1 World Name

Property:

```properties
level-name=world
```

This determines the name of the main world directory.

For example:

```properties
level-name=homelab-world
```

The server will use the corresponding directory for world data.

Changing the world name after creating a world does not rename the existing directory automatically. It may cause the server to create or load a different world directory.

Back up your world before modifying this setting.

### 6.2 World Seed

Property:

```properties
level-seed=
```

The world seed determines the initial world generation.

You can enter a seed value:

```properties
level-seed=123456789
```

Or leave it empty:

```properties
level-seed=
```

When blank, the server chooses a random seed during world generation.

**Important:** Changing this property after the world has already been generated does not regenerate the existing world.

### 6.3 Generate Structures

Property:

```properties
generate-structures=true
```

This controls whether structures such as villages and other generated structures are created during world generation.

To disable them:

```properties
generate-structures=false
```

This setting is mainly relevant when generating a new world.

### 6.4 Hardcore Mode

Property:

```properties
hardcore=false
```

When enabled:

```properties
hardcore=true
```

Players who die are placed into spectator mode instead of continuing normal survival gameplay.

Be careful when enabling hardcore mode on a world intended for casual multiplayer.

## 7. Network and Access Settings

These settings are especially important because our server is accessed by multiple devices.

### 7.1 Online Mode

Property:

```properties
online-mode=true
```

When enabled, the server authenticates players through Minecraft's account authentication system.

This is the preferred configuration for a normally authenticated Minecraft Java server.

Our initial experimental server used:

```properties
online-mode=false
```

This was done because the initial players used offline-profile launchers.

However, disabling online mode introduces a significant security risk.

In offline mode, the server does not reliably verify the connecting player's Minecraft identity.

A person may impersonate another player's username.

A whitelist does not fix this identity-verification problem.

**Recommendation:** Use `online-mode=true` when all players have appropriately authenticated Minecraft accounts.

Keep an experimental offline-mode server restricted to trusted participants through private network access. Do not expose it directly to the public internet.

### 7.2 Whitelist

In modern Minecraft Java server configurations, the property is:

```properties
white-list=true
```

When enabled, only permitted player profiles can join.

The property name uses a hyphen between `white` and `list`.

It is separate from the server console command named `whitelist`.

The whitelist is particularly useful for small private multiplayer servers.

Remember that its identity protection depends on the server's authentication configuration.

### 7.3 Enforce Whitelist

Property:

```properties
enforce-whitelist=true
```

This controls whether players who are not on the whitelist are removed when the whitelist is enforced or reloaded.

For a private server, enabling it can help ensure that non-whitelisted players are not allowed to remain connected.

### 7.4 Allow Flight

Property:

```properties
allow-flight=false
```

This controls whether players using flight are permitted without being kicked by the server's movement checks.

Do not change it unnecessarily.

If a legitimate gameplay modification causes false flight detections, investigate the actual cause before changing this property.

### 7.5 RCON

Property:

```properties
enable-rcon=false
```

RCON provides remote access to the server console.

For this initial homelab setup, leave it disabled.

Exposing a remote administrative interface can introduce serious security risks.

PaperMC's documentation warns that RCON traffic is not encrypted and should not be used over untrusted networks.

We can manage the server through the Termux and tmux console instead.

## 8. Recommended Starting Configuration

The following is an example set of properties for a small experimental Android server.

It is not a replacement for the entire generated `server.properties` file.

Modify only the corresponding entries in your existing file.

```properties
motd=Android Homelab Minecraft Server
max-players=5
gamemode=survival
difficulty=normal
server-port=25565
server-ip=
view-distance=6
simulation-distance=4
level-name=world
level-seed=
generate-structures=true
hardcore=false
white-list=true
enforce-whitelist=true
online-mode=true
enable-rcon=false
```

### Why these values?

| Property | Example Value | Reason |
|---|---|---|
| `max-players` | 5 | Small experimental group |
| `gamemode` | survival | Normal multiplayer experience |
| `difficulty` | normal | Standard survival difficulty |
| `server-port` | 25565 | Default Java server port |
| `view-distance` | 6 | Conservative starting point |
| `simulation-distance` | 4 | Conservative starting point |
| `white-list` | true | Restrict player access |
| `online-mode` | true | Normal account authentication |
| `enable-rcon` | false | Avoid unnecessary remote administration |

If using the same experimental offline-mode setup as our initial implementation, the `online-mode` value will differ. Understand the security implications before doing so.

## 9. Managing Players Through the Minecraft Console

PaperMC provides commands for managing players.

These commands are entered into the Minecraft server console.

Remember that these are not normal Termux shell commands.

### 9.1 Enabling the Whitelist

```text
whitelist on
```

Enables the whitelist.

### 9.2 Adding a Player

```text
whitelist add PlayerName
```

Replace `PlayerName` with the player's exact Minecraft username.

### 9.3 Removing a Player

```text
whitelist remove PlayerName
```

Removes the specified player from the whitelist.

### 9.4 Listing Whitelisted Players

```text
whitelist list
```

Displays the current whitelist entries.

### 9.5 Checking Online Players

```text
list
```

Displays the players currently connected to the server.

### 9.6 Granting Operator Privileges

```text
op PlayerName
```

Grants operator privileges.

Operators have access to additional administrative commands.

Only grant these privileges to trusted administrators.

### 9.7 Removing Operator Privileges

```text
deop PlayerName
```

Removes operator privileges.

### 9.8 Changing Difficulty

```text
difficulty hard
```

Changes the server difficulty to hard.

Other available values include:

```text
difficulty peaceful
difficulty easy
difficulty normal
difficulty hard
```

### 9.9 Getting the World Seed

```text
seed
```

Displays the world seed in the server console.

Keep the seed private if you do not want other players to use it to discover the world.

### 9.10 Teleporting Players

```text
tp PlayerName OtherPlayer
```

Teleports one player to another player.

The actual player names must replace the placeholders.

### Console vs In-Game Commands

When using the Minecraft server console, commands are generally entered without a leading slash.

For example:

```text
whitelist list
```

When entering commands through the Minecraft game chat, use a slash:

```text
/whitelist list
```

Some commands may require operator permissions when entered in-game.

## 10. Applying Configuration Changes

After editing `server.properties`, save the file.

Then start PaperMC again.

If you are using tmux:

```bash
cd ~/minecraft
tmux new -s minecraft
```

Then start the server:

```bash
java -Xms512M -Xmx2G -jar paper.jar --nogui
```

Wait until the startup process completes.

Check the console for errors.

**Important:** Most `server.properties` changes are loaded during server startup. Restarting the server is the reliable way to apply them.

Avoid using `/reload` as a general replacement for a restart, particularly when managing plugins. PaperMC warns that reloading can cause plugin-related problems.

## 11. Checking Performance After Configuration

Configuration changes should be tested rather than assumed to improve performance.

After starting the server, observe:

- How smoothly players can move around.
- Whether chunks load quickly enough.
- Whether the server experiences delays.
- Whether the smartphone becomes excessively hot.
- Whether other applications remain responsive.

Modern PaperMC includes the `spark` profiler, which can help investigate server performance.

Check the server console:

```text
spark
```

PaperMC's current command documentation recommends spark for performance profiling rather than relying on older timings tools.

For a basic performance investigation, consult:

[PaperMC Profiling](https://docs.papermc.io/paper/profiling/)

Remember that client FPS and server performance are different measurements.

A player may experience low FPS because of their laptop's graphics settings even when the Android server is healthy.

## 12. Common Configuration Problems

### Problem 1: Server setting does not change

Possible causes:

- The wrong file was edited.
- The property was spelled incorrectly.
- The server was not restarted.
- The file was overwritten or regenerated.

Check the relevant entry:

```bash
grep -n "max-players" ~/minecraft/server.properties
```

### Problem 2: Whitelist blocks a friend

Check:

```text
whitelist list
```

Verify the exact username.

Also check the server's authentication configuration.

A whitelist in offline mode does not reliably verify player identities.

### Problem 3: Cannot connect after changing the port

Ensure the Minecraft client uses the new port.

For example:

```text
192.168.1.15:25565
```

The example address must be replaced with the actual server IP and configured port.

Also verify that the server is listening on the intended port.

### Problem 4: Server becomes slower after changing view distance

Higher view distance can increase world data loading, memory use and network traffic.

Lower it gradually and test performance.

Changing multiple performance properties simultaneously makes it difficult to identify which change helped.

### Problem 5: World seed appears unchanged

The `level-seed` property affects initial world generation.

It does not change the existing generated world merely because the setting was edited.

Use a new world directory or a separate test server when experimenting with seeds. Never delete your only existing world to test a new seed.

## 13. Security Considerations

Before allowing players to connect:

- Enable the whitelist.
- Use normal account authentication when possible.
- Restrict operator privileges.
- Keep RCON disabled unless specifically required.
- Avoid unnecessary public port forwarding.
- Back up the world before major changes.
- Avoid publishing private server configurations.

Our initial offline-mode experiment should remain private and limited to trusted participants.
